# 答案格式重试机制说明

## 功能概述
代码现在具备自动重试机制，当生成的答案不符合标准格式时（未找到 "So the answer is:"），会自动重新生成，最多重试指定次数。

## 重试机制工作原理

### 1. 标准答案格式
模型生成的答案**必须**包含以下格式：
```
[推理过程...]

So the answer is: [具体答案]
```

### 2. 触发重试的情况
当 `extract_final_answer()` 函数未能在生成的答案中找到 "So the answer is:" 时，会触发重试：
- ❌ 生成内容格式不标准
- ❌ 模型未按要求输出
- ❌ 响应被截断

### 3. 重试流程
```
尝试 1 → 生成答案 → 检查格式 → ✗ 失败
   ↓
等待 1 秒
   ↓
尝试 2 → 生成答案 → 检查格式 → ✗ 失败
   ↓
等待 1 秒
   ↓
尝试 3 → 生成答案 → 检查格式 → ✓ 成功 → 继续处理

如果所有尝试都失败 → 跳过该条数据
```

## 配置参数

### `MAX_GENERATION_RETRIES`
- **位置**: 代码顶部配置区域
- **类型**: 整数
- **默认值**: 3
- **说明**: 答案格式验证失败时的最大重试次数
- **建议值**: 
  - 2-3次：正常使用
  - 4-5次：模型输出不稳定时
  - 1次：快速测试（不重试）

```python
# 在代码中的配置位置
MAX_GENERATION_RETRIES = 3  # 答案生成重试次数
```

## 跳过数据的影响

### 对输出文件的影响
- ✅ 跳过的数据**不会**被写入输出文件
- ✅ 输出文件只包含成功生成标准格式答案的数据
- ✅ 数据索引会有间隔（如果有数据被跳过）

### 对统计的影响
- **尝试处理**: 范围内的所有数据条数
- **成功生成**: 正确答案数 + 幻觉答案数
- **跳过数据**: 所有重试都失败的数据条数

公式：`尝试处理 = 成功生成 + 跳过数据`

## 优化建议

### 减少跳过数据的方法

1. **提高重试次数**
```python
MAX_GENERATION_RETRIES = 5  # 从3增加到5
```

2. **增加输出token数**（避免答案被截断）
```python
MAX_OUTPUT_TOKENS = 800  # 从400增加到800
```

3. **调整温度参数**（提高输出稳定性）
```python
GENERATION_TEMPERATURE = 0.3  # 从0.7降低到0.3
```

4. **优化提示词**
   - 多次强调输出格式要求
   - 提供更多格式示例
   - 简化推理要求

### 处理跳过的数据

如果发现有较多数据被跳过：

1. **检查日志**：查看被跳过数据的问题特征
2. **调整配置**：根据上述优化建议调整参数
3. **二次处理**：专门针对跳过的索引重新运行
4. **人工审核**：检查是否是模型理解问题

## 断点续传与重试

### 断点续传模式下的行为
```python
RESUME_MODE = True
```

- ✅ 会读取已有输出文件
- ✅ 从已有数据末尾继续处理
- ✅ 新处理的数据追加到文件
- ✅ 跳过的数据不影响续传位置

### 示例场景
```
第一次运行：处理 0-100，跳过了索引 5, 23, 67
输出文件包含：97 条数据

第二次运行（RESUME_MODE=True）：
从索引 100 继续，不会重新处理 5, 23, 67
```

## 常见问题

**Q: 为什么会出现格式不标准的答案？**
A: 可能原因：
- 模型输出不稳定（temperature过高）
- 输出被截断（max_tokens过小）
- 提示词理解问题
- API返回不完整

**Q: 重试会影响性能吗？**
A: 会有一定影响：
- 每次重试增加 1 秒等待时间
- 重新调用 API 增加处理时间
- 但可以提高数据质量和完整性

**Q: 可以完全禁用重试吗？**
A: 可以，设置为1即可：
```python
MAX_GENERATION_RETRIES = 1  # 不重试
```

**Q: 跳过的数据可以单独处理吗？**
A: 可以，记录跳过的索引，然后：
```python
START_INDEX = 5
END_INDEX = 6  # 只处理索引5
```

**Q: 如何批量处理所有跳过的数据？**
A: 需要从日志中收集跳过的索引，然后循环处理每个索引。

## 最佳实践

1. **初始设置**: 使用默认重试次数3次
2. **测试阶段**: 处理少量数据验证配置
3. **正式运行**: 启用断点续传，应对意外中断
4. **监控日志**: 关注跳过数据的比例
5. **参数调优**: 根据跳过率调整配置
6. **数据补全**: 最后专门处理跳过的数据
